## 2. وصف المشروع

برنامج Java يقيس زمن تنفيذ خمس خوارزميات ترتيب بدقة **الميكروثانية (µs)** باستخدام `System.nanoTime()`،
على مصفوفة بحجم ثابت **N = 100,000** وعلى أربع حالات بيانات:

1. **Random** — أعداد عشوائية تمامًا.
2. **Sorted Reversely** — مرتبة تنازليًا.
3. **Sorted Partially** — مرتبة بنسبة ≈ 80% مع 20% قيم عشوائية متفرقة.
4. **Sorted Fully** — مرتبة تصاعديًا.

الخوارزميات: Selection Sort، Insertion Sort، Bubble Sort (مع تحسين `swapped`)، Merge Sort، Quick Sort (المحور = آخر عنصر).

## 5. تحليل ومناقشة النتائج

### 5.1 مقارنة O(N²) مع O(N log N)

- خوارزميات **Selection / Insertion / Bubble** تنفّذ حوالي N²/2 ≈ 5×10⁹ عملية في أسوأ الحالات عند N = 100,000، ولذلك استغرقت من **ثوانٍ إلى ~18 ثانية** (Bubble على البيانات العشوائية: ≈ 18.5 ثانية).
- **Merge Sort** و**Quick Sort** تنفّذ حوالي N·log₂N ≈ 1.7×10⁶ عملية، فاستغرقتا **أجزاء من الثانية** (≈ 8–48 ms).
- في الحالة العشوائية كان Quick Sort أسرع من Bubble بنحو **1,100 مرة**، ومن Selection بنحو **300 مرة**. الفرق ينمو بزيادة N لأن النسبة بين N² و N·log N تساوي تقريبًا N/log N.
- **Selection Sort** لا يتأثر كثيرًا بحالة البيانات لأنه يجري دائمًا نفس عدد المقارنات (N²/2) في كل الحالات، وتختلف الأزمنة قليلًا فقط بسبب عدد التبديلات وتنبؤ الفروع (Branch Prediction).
- **Bubble Sort** هو الأسوأ في الحالة العشوائية لكثرة التبديلات (Swaps) المكلفة، وليس فقط المقارنات.

### 5.2 أفضل خوارزمية للبيانات المرتبة والمرتبة جزئيًا

**الحالة المرتبة تمامًا:** أفضل خوارزميتين هما **Insertion Sort (87 µs)** و**Bubble Sort المحسّن (294 µs)**؛ كلاهما O(N) في أفضل حالة:

- *Insertion Sort*: كل عنصر يُقارن مرة واحدة فقط مع العنصر الذي قبله ولا يحدث أي إزاحة، فتكون الدورة الداخلية صفرية.
- *Bubble Sort*: دورة واحدة بدون أي تبديل فيتوقف بفضل المتغير `swapped`.
- أما Selection فلا يملك آلية للتوقف المبكر فيبقى O(N²)، وMerge يبقى O(N log N) دائمًا.
- Quick Sort (بمحور آخر عنصر) هو الأسوأ هنا — انظر 5.3.

**الحالة المرتبة جزئيًا (≈ 80%):** الأفضل هو **Quick Sort (7,510 µs)** ثم **Merge Sort (9,109 µs)**؛ وجود 20% قيم عشوائية يكسر النمط المرتب فيصبح اختيار المحور شبه متوازن، وتبقى Merge/Quick عند N log N. أما **Insertion Sort (125,277 µs)** فهو أفضل بكثير من Selection وBubble (≈ 17–70 مرة) لأن زمنه يتناسب مع عدد الانقلابات (Inversions) في المصفوفة، وهي قليلة نسبيًا هنا، لكنه يبقى أبطأ من Merge/Quick بأكثر من 10 مرات. أما Bubble فيفقد ميزة التوقف المبكر لأن العناصر العشوائية المتفرقة تبقى تحتاج عدة دورات.

### 5.3 سلوك Quick Sort في الحالة العكسية والكاملة وأثر عنصر المحور (Pivot)

- النتائج: Quick Sort أخذ **3.64 s** في الحالة العكسية و**4.40 s** في الحالة المرتبة، مقابل **16 ms** في العشوائية — أي أبطأ بحوالي **220–270 مرة** في نفس الحجم.
- السبب: المحور المختار هو **آخر عنصر**. في المصفوفة المرتبة تصاعديًا يكون المحور **أكبر عنصر** دائمًا؛ وفي المرتبة تنازليًا يكون **أصغر عنصر** دائمًا. لذلك يقسّم `partition` المصفوفة إلى جزء بحجم **N−1** وجزء فارغ **0** بدل نصفين متساويين.
- تصبح علاقة التكرار: T(N) = T(N−1) + O(N) ⇒ **T(N) = O(N²)** (حوالي N²/2 مقارنة) بدل T(N) = 2T(N/2) + O(N) = O(N log N).
- ينتج عن ذلك أيضًا عمق تعاود يساوي **N** (≈ 100,000 استدعاء متداخل) بدل log N، وهو ما يسبب `StackOverflowError` مع Stack الافتراضي، لذلك شغّلنا البرنامج داخل Thread بحجم Stack كبير.
- **الحلول الشائعة** لتفادي ذلك: اختيار محور **عشوائي** (Randomized Pivot)، أو **وسيط الثلاثة** (Median-of-Three: أول/وسط/آخر)، أو خلط المصفوفة (Shuffle) قبل الترتيب، أو الاستدعاء التعاودي على الجزء الأصغر أولًا والتكرار (Loop) على الجزء الأكبر لتقليل عمق الـ Stack.

### 5.4 جدول التعقيد النظري

| الخوارزمية | الأفضل | المتوسط | الأسوأ | الذاكرة الإضافية |
|---|---|---|---|---|
| Selection Sort | O(N²) | O(N²) | O(N²) | O(1) |
| Insertion Sort | O(N) | O(N²) | O(N²) | O(1) |
| Bubble Sort (محسّن) | O(N) | O(N²) | O(N²) | O(1) |
| Merge Sort | O(N log N) | O(N log N) | O(N log N) | O(N) |
| Quick Sort | O(N log N) | O(N log N) | O(N²) | O(log N) متوسطًا / O(N) أسوأ |

### 5.5 الخلاصة

1. للبيانات الكبيرة العشوائية استخدم **Quick Sort** (الأسرع عمليًا) أو **Merge Sort** (أداء مضمون وثابت)، وتجنّب خوارزميات O(N²).
2. للبيانات المرتبة أو شبه المرتبة **Insertion Sort** ممتاز عندما تكون الانقلابات قليلة جدًا.
3. أداء **Quick Sort** يعتمد على اختيار المحور؛ المحور الثابت (أول/آخر عنصر) خطر على البيانات المرتبة.
4. **Merge Sort** أكثر الخوارزميات استقرارًا في الأداء عبر جميع الحالات، بثمن ذاكرة إضافية O(N).
